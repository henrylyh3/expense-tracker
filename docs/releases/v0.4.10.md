# v0.4.10+19

Browser guests can open a newly generated private link and send expenses while the host is closed. Link creation stores an encrypted trip snapshot in the existing Discord relay, so initial categories/currencies require no live host. Every expense leaves the browser's pending queue once Discord returns its message receipt; subsequent expenses send immediately without waiting for a host reply. Sent history remains encrypted on the guest device. Successfully sent submissions can be imported when the desktop opens later, without the guest returning to the page.

Expiry applies to Discord's trusted creation/last-edit timestamp, allowing pre-expiry deliveries to be imported later while rejecting late posts and edits. One-way browser submissions require no host acknowledgement. Expired invitations receive no fresh ledger snapshot during late imports. Existing native guest acknowledgements and host deduplication remain compatible. Ledger ownership, app IDs, data paths and signing keys are preserved.

Validation: Flutter analysis clean; 24 focused native sharing/widget tests and 14 web protocol tests passed. Tests cover host-offline initial loading, multi-expense delivery without replies, partial uploads/restart, lost receipt deduplication, older cached receipts, encrypted metadata, failed invitation cleanup, late import and expired-message edits. Live browser checks use fictional data, not a real bot/channel.

Public native publication remains blocked by unavailable original Android signing credentials and desktop release certificates/notarization configuration. Validation bundles do not establish signed, installed-device or live Safari/Discord acceptance.
